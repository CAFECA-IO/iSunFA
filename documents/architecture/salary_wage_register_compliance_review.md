# 工資清冊：對照臺北市勞動局範本的檢視

> 撰寫：20260914 - Julian
> 對照物：臺北市政府勞動局「工資清冊」範本（使用者提供，`64713572967.xlsx`）
> 本專案的工資清冊 ＝ `salary_record_csv.ts` 的 CSV 匯出
> 相關：`salary_company_profile_plan.md`、`issue_annual_leave_register.md`

## 0. 先講範本的份量

**這份範本不是法規。** 勞基法 §23 II 對清冊的要求是「將發放工資、工資各項目
計算方式明細、工資總額等事項記入」，三項全是金額；範本的欄位比那細得多。

所以本文的「不符」一律指**不合範本**，不是「違法」。但範本的份量不低：
它是主管機關自己發的格式，而客戶的場景正是**勞檢調閱**——
勞檢員手上拿的很可能就是這張表。位階是：**法條 ＞ 主管機關範本 ＞ 實務慣例**。

（這一點值得先寫清楚，因為本模組上一輪才因為把「實務慣例」誤當「法定必載」
而做了一整頁功能。見 `salary_company_profile_plan.md` §1。）

## 3. 不符之處

### 3.1 ⚠️ 最嚴重：註記 2「金額不得合併記載」

範本把加項拆成五欄（平日加班費／假日加班費／國定假日出勤／業績獎金／其他獎金），
固定給付另外拆成四欄（伙食津貼／職務加給／交通津貼／全勤獎金），
並在表尾明文寫**不得合併記載**。

本專案兩處都是合併的，而**兩處的性質不同**：

#### 3.1.1 加班費 —— 這是**報表**問題，資料還在

CSV 只有兩格：「加班費（應稅）」「加班費（免稅）」。

但**輸入端是按倍率分開收的**，而倍率本身就編碼了類型（勞基法 §24）：

| 倍率 | 對應                              |
| ---- | --------------------------------- |
| 1.33 | 平日延長工時前 2 小時（加給 1/3） |
| 1.66 | 平日再延長 2 小時（加給 2/3）     |
| 2.00 | §32 IV 天災事變，加倍發給         |
| 2.33 | 休息日前 2 小時（另再加給 1⅓）    |
| 2.66 | 休息日 2 小時後（另再加給 1⅔）    |

也就是「平日加班費」＝ 1.33 ＋ 1.66 那兩格，「假日加班費」＝ 2.33 ＋ 2.66。
**資料在 `inputSnapshot` 裡，只是沒有被拆出來報。**

→ 可以只改 CSV 的欄位組法解決，不動資料模型。

**但有一格對不上：「國定假日出勤」。** §39 的休假日出勤工資加倍發給，
而計算機目前沒有一個專屬倍率代表它 —— 2.00 那一格的語意是
§32 IV 的天災事變。兩者都是「加倍」但法源與情境不同，
混用會讓清冊上的「國定假日出勤」與實際不符。這一格需要產品決定。

#### 3.1.2 其他加給 —— 這是**資料模型**問題，補欄位解決不了

計算機的加項輸入只有兩個數字：

```ts
otherAllowanceWithTax: number; // 其他加給（應稅）
otherAllowanceWithoutTax: number; // 其他津貼（免稅）
```

範本要求分列的**職務加給、交通津貼、全勤獎金、業績獎金、
其他獎金（年終／三節／福利）**全部併在這兩個數字裡 ——
而且是在**使用者輸入的當下**就併掉了，`inputSnapshot` 裡也救不回來。

這是本次檢視最實質的一項：**它不是 CSV 的問題，是計算機輸入模型的問題。**
要合範本，得讓加項變成可列舉的項目清單（名稱＋金額＋應稅與否），
而那會動到計算機的表單、快照結構、薪資單版面與既有紀錄的相容性。

### 3.2 表頭沒有公司名稱與年月

範本表頭是 `____公司　工資清冊　__年__月份`。本專案的 CSV 從第一列就是欄名，
沒有任何表頭；年月放在每一列的「期間」欄。

> **這一項要特別說明，因為我上一輪對它的判斷反覆過兩次。**
>
> 我先把「清冊沒有雇主識別」寫成法遵缺口（R1），核對 §23 II 之後
> 自我否證（條文只要求金額），把它降成可讀性問題。
> **範本顯示我第一次的直覺是對的，但理由找錯了**：
> 它的依據不是法條，是主管機關的範本格式。
>
> 結論因此再修一次：**這一項該做，份量是「合範本」而不是「合法」。**

P1 已經把 `entityName` 存下來了，`salary_company_profile_plan.md` 的 P3
（CSV 前言）補上即可 —— 而那一階段的案由現在從「可讀性」升回「勞檢實務」。

### 3.3 缺「部門/職稱」

`SalaryCalculatorEmployee` 沒有這兩個欄位（HR 模組的 `Employee` 有
`Department` / `JobTitle` 關聯，但計算機刻意與它分離，見
`salary_record_module_plan.md` §3.1 的理由）。

範本把它放在姓名之前，是勞檢清點人員編制時的第一個對照維度。

### 3.4 缺「代扣職福會福利金」專欄

本專案只有「其他溢扣／補收」一格。範本把它獨立成欄，並在註記 3 說明
它的前提（依法設立職工福利委員會）與上限（工資的 0.5%）。

併在「其他溢扣／補收」裡同樣踩到註記 2 的「不得合併記載」。

### 3.5 「應發工資」與「月薪資合計」不是同一個東西

看範本的欄序：本俸 → 伙食津貼 → 職務加給 → 交通津貼 → 全勤獎金 →
**應發工資**（K）→ 才是「加項」群組（加班費等，L–P）→ 自負額（Q–V）→
**實發工資**（W）。

也就是範本的 `應發工資` 是**固定給付的小計，不含加班費與獎金**，
而 `實發工資 ＝ 應發工資 ＋ 加項 － 自負額`。

本專案的「月薪資合計」（`totalMonthlySalary`）是**應稅＋免稅的全部合計，
含加班費**。兩者名字相近、位置相近、意思不同 ——
直接把「月薪資合計」放到「應發工資」那一欄會是錯的。

## 5. 我沒有做的判斷

- **範本是否為勞檢必用格式**：沒有查證。它是臺北市勞動局提供的範本，
  但「勞檢一定照這張表對」是推測，不是事實。其他縣市的格式可能不同。
  值得直接問客戶：他們遇到的勞檢實際拿的是哪一份。
- **「國定假日出勤」該怎麼對應**：§39（休假日出勤加倍）與 §32 IV
  （天災事變加倍）都是 2.00，但法源不同。這要產品／會計拍板。
- 本文只比對**欄位**，沒有比對每一格的**計算方式**是否與範本預期一致。
