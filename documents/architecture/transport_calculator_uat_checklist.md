# 物流碳足跡計算器:真機驗收 Checklist

> **對象分支**:`feature/transport_carbon_route_optimization`(issues 01–09)+ `feature/transport_multimodal_extension`(issues 10–11)
> **決策脈絡**:`documents/architecture/decisions/013_transport_multimodal_and_disclosure.md`
> **為什麼需要**:上述變更跨引擎 / UI / PDF / CSV / worker 五層,單元測試(33 項)只覆蓋純函數;PDF 截圖、瀏覽器導覽、Excel 讀取這三類行為單元測試無法驗證。

---

## 0. 環境準備(必做,順序不可換)

- [ ] `git checkout feature/transport_multimodal_extension`
- [ ] `npx prisma generate && npx prisma db push`(若切分支後 schema 有變)
- [ ] **重啟 worker**:停掉舊的 `npm run worker` 再重新啟動
      ⚠️ worker 是長駐程序,不會熱重載;本分支改了 issuer / recorder / skill,不重啟則驗收的是舊程式碼
- [ ] `npm run dev` 啟動 dev server
- [ ] 確認 OSRM 有起來:`curl "http://127.0.0.1:20025/route/v1/driving/121.56,25.03;120.30,22.62"` 應回 `"code":"Ok"`
      (沒起來的話所有陸路都會退估算值,驗收第 2、3 項會全部顯示「估算值」徽章 —— 這是預期行為,但無法驗收真實路網情境)

## 1. Worker 訂單關聯(issues 05/06)

- [ ] 發起一筆**新的**碳排核算(任意路線)
- [ ] 檢查 `issues/<錢包位址>_<新taskId>/context.json` **存在**,且內含 `orderId`
      → 這是修復生效的直接證據;若不存在,worker 沒重啟
- [ ] 等 worker 跑完(約 1 分鐘,六個 daemon 各 10 秒間隔),歷史報告頁該筆狀態應變 **completed**
- [ ] 點「載入」→ 報告內容正常顯示(不是空白)
- [ ] worker log 不應出現 `⚠️ Task ID ... matches multiple orders`

## 2. 運輸方式適用性(issue 01)

**國內短程**:武嶺 → 台北 101(或任兩個台灣本島地點)

- [ ] 分析頁**只出現「純陸運」按鈕**,海運 / 空運 / 海陸空按鈕完全不顯示(不是灰掉,是不存在)
- [ ] 里程核算批次檢視同一路線,方案切換鈕亦只有純陸運
- [ ] 標頭碳排徽章顯示正確數字(非 0),可用 `距離 × 重量(t) × 0.11289` 手算核對

**跨海**:台北 → 上海

- [ ] 海運與空運按鈕出現;純陸運按鈕不出現
- [ ] 標頭徽章顯示海運方案總計(**不是 0**)——這是 issue 09 的迴歸點

---

## 3. 估算值誠實標示(issue 07)

**非台灣路線**(OSRM 圖資範圍外),如 巴黎 → 柏林

- [ ] 展開方案後,陸運接駁段的里程旁出現琥珀色**「估算值」**徽章
- [ ] hover 徽章顯示說明:「路網圖資未涵蓋此區域,以直線距離 ×1.2 推估」
- [ ] 標頭碳排徽章顯示 `~` 前綴(如 `~89.1 kg CO₂e`)
- [ ] 台灣路線**不應**出現估算值徽章(真實路網)

---

## 4. 海陸空聯運(issue 10)

**跨洲內陸→內陸**,如 布拉格 → 芝加哥

- [ ] 分析頁出現**「海陸空聯運專案」**按鈕(靛藍色,Layers 圖示)
- [ ] 點開後區段列表顯示 **5 段**,依序為:陸 → 海 → 陸 → 空 → 陸
- [ ] 第 3 段終點與第 4 段起點是**同一個中轉機場**名稱
- [ ] 各段碳排相加 = 該方案總計(手算或用計算機核對,允許末位捨入差)
- [ ] 國內短程路線**不應**出現此方案(適用性規則屏蔽)

## 5. 匯出勾選與 PDF 拆分(issue 02 + 10)

- [ ] 點「匯出報告」→ 彈出勾選選單,**只列出適用方案**(國內路線只有純陸運)
- [ ] 取消勾選其中一項 → 確認匯出 → 產出的檔案不含該方案
- [ ] 全勾多方案 → 下載 zip,解開後:
  - [ ] 每個方案**各自一份獨立 PDF**(不是一份多頁混合)
  - [ ] 檔名可辨識方案:`*_land_only.pdf` / `*_sea_multimodal.pdf` / `*_air_multimodal.pdf` / `*_sea_land_air_multimodal.pdf`
- [ ] 開啟其中一份 PDF:
  - [ ] **地圖有正確渲染**(不是空白或透明)⚠️ develop 期間 maplibre 升到 6,這是本次最高風險項
  - [ ] 區段列表完整、係數與來源可見
  - [ ] 若該段為估算值,PDF 上也應看得到「估算值」徽章
- [ ] 匯出過程覆蓋層顯示進度「正在產生第 x / y 份報告」

## 6. 總結 CSV(issues 03 / 07 / 08 / 11)

多筆批次匯出 → zip 內 `summary.csv`,用 Excel 開啟(注意 BOM 應讓中文正常顯示):

- [ ] 檔頭 `#` 行揭露公式、三個係數、Weight 欄語意、`Estimated? = Y` 說明
- [ ] **一段一列**(long format),同一路線的多個方案連續數列
- [ ] 欄位含 `From Lat/Lng`、`To Lat/Lng`——港口與機場的經緯度有值
- [ ] `Factor` 與 `Factor Source` **逐列**標注(不是只在檔頭)
- [ ] `Plan Total CO2e` 只在每個方案的**最後一段**有值
- [ ] 隨機挑一列手算驗證:`Distance × (Weight/1000) × Factor = Leg CO2e`
- [ ] 挑一個方案驗證:各段 `Leg CO2e` 相加 = `Plan Total CO2e`
- [ ] `Weight (kg)` 欄顯示**該列真實重量**(若各列重量不同,欄值應不同)
- [ ] 不適用方案**完全沒有列**(不是 N/A 填充)
- [ ] fallback 段 `Estimated?` = `Y`,真實路網段 = `N`

## 7. 歷史導覽(issue 04)

- [ ] 在報告檢視按 F5 重新整理 → 報告應**重新載入並顯示**(不是空白)
