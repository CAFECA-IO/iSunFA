## 問題

**畫面看起來沒事,可是東西不在。**

## 做了什麼(依重要性)

| # | 主題 | 一句話 |
| --- | --- | --- |
| 1 | 長呼叫被閘道切斷 | 心跳串流:每 20 秒送一個位元組,`proxy_read_timeout` 是**閒置**逾時,因此 nginx 一行都不用動(先前的「調大逾時」解法有安全隱患,已撤) |
| 2 | 匯入通知端點從未成功過 | `recipientPublicKey ?? address` —— address 是 `0x…` 不是 base58 xpub,ECIES 每次都炸,**這解釋了連兩輪「匯入後聊天室沒有記錄」** |
| 3 | 兩個廠址共用同一棵子樹 | 表3.8 的「總公司」與「屏東分公司」編號都是 `(1)`,而我拿它當節點前綴 → 第 3 層以下完全併在一起。**所有守恆測試都通過**,因為合併不改變總量 |
| 4 | 解析完不套用就消失 | 新 model `CarbonPendingImport`(E2EE)+ 對話留一則「報告解析完成」+ 預覽卡多一條「稍後再說」 |
| 5 | 匯入十幾次重送整份 PDF | 改為先上傳取 cid(2 MB × 14 ≈ 28 MB → 一次);附帶讓匯入檔第一次真的經過掃毒 |
| 6 | 逐房進度提示 | 提示原本只有一格,B 房任何動作會清掉 A 房的進度 → 使用者以為停了,重新上傳一次 |
| 7 | 超長標籤一票否決整張圖 | 一個 43 字的合法標籤讓另外 30 個節點的圖被拒 |
| 8 | 會話清單沒有排序 | 是插入順序,所以**新對話出現在最底部**;改為依真實最後活動時間 |
| 9 | 五層桑基圖拆兩張三層 | mermaid 把標籤畫在節點右側,1:1 的層必然重疊 —— 這是佈局事實不是參數問題 |
| 10 | 月別分層只在重載前有效 | Zod 預設 strip 未宣告的鍵,而 schema 沒宣告 `tradingTimestamp` → 解密後時間戳被洗掉 |
| 11 | 一次失敗變永久失敗 | 還原失敗的 channel 被永久標記,網路抖一下那房就再也不還原 |
| 12 | 工具列蓋住聊天面板 | 定位元素畫在未定位元素之上 |

## 已知限制(寫進 PR body)

- cid 是「知道即可讀」的能力憑證,無擁有者檢查 —— 與既有聊天附件同一慣例;要收緊是獨立一票
- 上傳失敗退回直傳時 cid 為 null,重載後不能重試失敗章節
- **月別分層需要有憑證/活動數據的帳本會話才看得到** —— 匯入報告的表3.8 是年度合計,
  沒有逐筆日期,所以純匯入的會話上不會出現月別層(見下)
