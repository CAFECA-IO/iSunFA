# 表3.8 廠址判定會誤中「(3) 見附錄」這類行,並靜默套用到後續各列

> **狀態**:📋 2026-08-07 開票(T3 PR review 低優先項),**需要樣本才能收斂**

- 嚴重度:P2(誤判時會把排放歸給不存在的廠址;目前輸入受限,發生率低)
- 檔案:`TABLE38_STANDALONE_SITE_PATTERN`

## 問題

```
/^\(\s*[0-9]+\s*\)\s*[^\s|]{1,20}$/
```

這個 pattern 用來認出「獨立成行的廠址標題」,認到就把 `currentSite` 換掉,
後續各列都歸到那個廠址。但它也會match:

- `(3) 見附錄`
- `(2026)年報`
- 任何「括號數字 + 20 字以內無空白字串」的行

誤判之後不會有任何錯誤,只會讓一段排放被歸到一個不存在的廠址 ——
而廠址是查證時要求佐證的單位。

## 為什麼現在不直接收緊

要收緊就得知道真實的廠址名長什麼樣。我們手上只有高興昌一份報告,
它的廠址都帶「公司」後綴(總公司/台北分公司/屏東分公司),
但據此加上後綴白名單,會在第二份寫「(1) 台中」的報告上以**同樣靜默的方式**出錯 ——
只是換一個方向:該認的沒認出來,整段排放歸到上一個廠址。

用一份樣本推導出來的規則,在第二份樣本上失敗的機率不低於現在。

## 拿到樣本前的中間作法(建議先做這個)

**讓推論可見,而不是收緊推論。**

把系統推斷出來的廠址清單顯示在匯入確認畫面上(「本次辨識到 3 個廠址:總公司、
台北分公司、屏東分公司」),讓使用者在匯入當下就能發現多出一個「見附錄」。

這不會讓誤判消失,但會把它從「查證階段才發現數字掛錯廠」變成
「匯入當下看一眼就知道」。與本模組其他地方的同一條原則一致:
沒畫出來、或推論出來的東西,必須說出來。

## 收斂條件

蒐集 3–5 份不同企業的盤查報告書表3.8,從實際的廠址寫法推導 pattern。
在那之前不改 pattern。

## 驗收

- 匯入確認畫面列出辨識到的廠址清單。
- 清單與原文表3.8 的廠址逐一對得上(含數量)。
