# PDF:圖表比例失控、表頭整片黑、窄欄文字被擠成直書

> **狀態**:📋 2026-08-07 開票(Emily UAT),未修

- 嚴重度:P1(輸出可讀性;不影響數值正確性)
- 檔案:`PDF_PRINT_STYLE`(`src/constants/pdf_tool.ts`)與 mermaid 渲染樣式

## 三個症狀(同一份 85 頁輸出)

1. **圖表比例失控**:p.10 的類別流程圖被放大到一頁只放得下四個節點,
   而同一份裡的桑基圖尺寸正常。看起來是不同 mermaid 圖種在列印樣式下的
   寬度基準不一致 —— flowchart 沒有被限制在可列印寬度內。

2. **表頭整片黑**:表2.1 的表頭是一整塊純黑,文字完全看不見。
   推測是表頭背景色用了 CSS 變數或 `oklch()`,而 html2canvas 解析不了,
   fallback 成黑色。同一個成因在 `10` 那票裡被列為空白 PDF 的可能來源之一。

3. **窄欄文字被擠成直書**:表2.1 第一欄每個字一行,整欄變成直排。
   欄寬被壓到一個字元寬,是欄數過多 + 沒有設最小欄寬的結果。

## 關鍵線索:預覽是對的,下載才壞

2026-08-07 UAT 補充。同一張表3.6:

- **預覽**:欄寬正常、橘色表頭、數字橫排,可讀。
- **下載**:表頭是一整塊黑、第一欄擠成直書、數字被拆成多行。

內容相同、程式相同,差別只有下載時額外注入的列印樣式(`PDF_PRINT_STYLE`)。

因此上面那「三個症狀」很可能不是三件事,而是**同一個根因**:
光柵化時的版面寬度與預覽的版面寬度不一致。欄數多的表格被壓窄就變直書;
mermaid 的 SVG 有固定內在尺寸、不隨之縮小,於是在變窄的頁面上顯得過大。
表頭黑是另一條線(顏色解析失敗),但同樣出在那份樣式。

**下一輪的第一件事是驗證這個假設,不是動手改** ——
用無頭 Chromium 分別在「預覽樣式」與「列印樣式」下量同一張表的欄寬與表頭像素色。
假設成立的話,修的是那份列印樣式的寬度基準,一處而非三處;
不成立就得拆開處理,而那會是完全不同的工作量。

## 為什麼分開開票

這三個都在**光柵化之前**就已經決定了 —— 是列印樣式的問題,不是分頁或畫布的問題。
`10` 那票處理的是「畫不畫得出來」,這票處理的是「畫出來對不對」。
混在一起會讓兩邊的驗收條件互相干擾。

## 建議

先做 2(表頭黑):它讓表格完全不可讀,而且成因最明確 ——
把列印樣式裡所有顏色改成 html2canvas 解析得了的固定色,不依賴 CSS 變數。
可用今天建立的無頭 Chromium harness 直接量測表頭像素色。

3 次之,1 最後(需要逐一檢查各 mermaid 圖種的寬度基準)。

長遠的解法仍是 `13`(伺服端向量列印)——這三個症狀都是光柵化路徑特有的。
