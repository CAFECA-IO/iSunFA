## 做了什麼

### 1. 讓失敗說得出原因(前提,不是加值)

- `fetchSectionPageIndex` 成功時原本零 log。它是整條管線**最上游、唯一非決定性**的輸入
  (一次 LLM 呼叫,同一份 PDF 兩輪給不同答案),出事時卻無從回溯。現在記錄索引與每章切片。
- `source table dropped` 原本只記 `reason`,而 `not_a_table` 檢查的正是**前兩行** ——
  不印出來就等於「知道被擋了,但永遠不知道為什麼」。現在連被拒內容的開頭三行一起記。
- 缺表3.8 但同節有表3.6/3.7 → 報告裡直接寫出原因與後果,不再靜默少一張圖。

**共同原則:被擋下的東西,要連「擋它的那個依據」一起記。**

### 2. 三種版面各留一份 fixture

| 版面 | 特徵 |
| :-- | :--- |
| A(08-03) | 廠址欄逐列重複,合併儲存格攤平 |
| B(08-04) | 廠址與類別小計各自獨立成列,每廠址前重複表頭 |
| **C(08-05)** | **拆成三張子表格,廠址名在表格外的純文字行** |

同一份 PDF、同一組提示詞,**版面一輪換一次**。三份都留 —— 任何一種隨時會回來。

C 的判準收緊到明表(`(n)` 前綴 + 短名 + 整行到此為止),不用排除法:
表格標題「表3.8 **各公司**溫室氣體…」含「公司」,沿用 `isSiteCell` 的備援訊號會把標題認成廠址。

### 3. 排版不是內容:`<br>` 在讀取時清除

模型以 `<br>` 表示 PDF 折行。畫面把它原樣印出(`rehype-raw` **刻意不開**,三處註解記載,理由是 XSS;
下載 PDF 走同一個 DOM,沒有第二套渲染能救)。

但顯示只是最表面。整條匯入路徑**一處都沒清洗儲存格文字**,`<br>` 一路帶進解析器造成四個**靜默**錯誤:
數字解不出、`(1) 總公<br>司` 成為污染的廠址名一路帶進桑基圖節點、子代碼對不到、重複表頭被當成資料列。

存下來的原文一字不改(逐字照錄的合約),清除發生在讀取時。
**兩個呼叫端、一份實作** —— 兩層各寫一份 regex 遲早不一致,而不一致的表現是
「圖上的廠址名跟畫面上的不一樣」。

補空白的判準改過一次:第一版用「兩側是不是中日韓字元」,結果 `1.<br>1` 兩側是 `.` 與 `1`
都不是中日韓 → 補了空白 → 子代碼對不到 → **整列被丟掉**。
折行落在數字中間是 PDF 表格的常態,那一版等於把最該修的情形修壞。
正解是「原文本來有沒有空白」,只發生在兩側都是 ASCII 英數時。

### 4. 使用者說過的話不該因為系統回不出來就消失

`recordUserMessage` 原本排在 LLM 呼叫**之後**。逾時或撞額度,那則訊息就永遠不進 DB ——
畫面上還在(本機 echo),重載就沒了。而匯入正是最會燒額度的操作
(11 章 + 最多 11 次 gap-fill + 5 次結構圖,額度 12 次/分鐘)。已提到呼叫之前。

順帶補上 `loadHistory` 解密失敗的 log:原本空 catch,整頁解不開時第一頁載入是**整組覆蓋**,
聊天紀錄整個變空 —— 與「這房間本來就沒講過話」完全同形,而資料其實還在 DB 裡。

### 5. 推播連線:我們自己弄斷的

`WebSocket is closed before the connection is established` 是**客戶端在 CONNECTING 狀態
呼叫 close()** 才會印的(伺服端拒絕會是 403/502)。

`subscribeChatroom` 每次呼叫都 `new Centrifuge()`、清理時 `disconnect()`;
而訂閱 effect 的依賴鏈一路連到 `sessionAccess`,它在掛載後至少三處會非同步寫入。
每寫一次 → effect 重跑 → 連線關掉重建,頁面剛載入那幾百毫秒內連續數次。

**連線不該隨 React 的 render 生命週期起落。** 改為單一實例,換房只換訂閱的 channel。
連線狀態原本只寫進沒人消費的 `isError`(推播壞掉完全靜默),現在輸入列會顯示。

這件事直接關係到「聊天室斷掉」:`/api/v1/chat/carbon` **早就是雙軌**
(推播 + HTTP 回帶,以 `message.id` 去重),斷線保底一直都寫好了,只是推播那一軌沒在運作。
實測已回到 `101 Switching Protocols`。

### 6. 不靠拉長連線解長請求

`proxy_read_timeout 300s` 的提案**被否決**(Emily):全站共用、把慢速連線攻擊的成本降低五倍,
而且它沒解決任何事 —— 只是把 60 秒的轉圈變成 300 秒。
`chore/gateway_proxy_timeout` 標為 wontfix,誤提交進功能分支的那份已退回。

改為縮小工作本身:章切成最多 4 節的工作單元,ch1(7 節)、ch3(6)、ch9(5)各切兩份。
切的單位是**節不是頁** —— 以頁切會把跨頁表格切成兩半(表4.8 跨 8 頁),
那是拿無聲的資料損失換請求跑得完。

**已知救不了的情形,寫成測試**:ch4 只有 3 節卻跑 2.5 分鐘,成本集中在 4.2 一節的九張表
(輸出 20220 tokens)。節是這個維度的最小單位。

### 7. 封存清單自己捲動

封存區塊是 `flex-1` 捲動區的兄弟節點,而側邊欄根容器沒有高度上限。
16 筆展開時整個側邊欄被撐過視窗高度,「設定」被推出畫面,歷史清單的捲動條也失去意義。
