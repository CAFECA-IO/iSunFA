# Bug: 結構圖被限流無聲吃掉,以及「一個點的時間軸」

> **狀態**:✅ 已完成(2026-08-04 回顧確認);殘留驗收綁 issue 01

**Labels**: bug, carbon, P2
**Branch**: `feature/esg_report_ingestion`(已修,`9aaf4bb06`)

## 現象一:1.4 / 1.5 / 3.3 沒有圖,1.1 / 2.3 有

匯入一份報告會連續發出 11 章 + 最多 11 次 gap-fill 呼叫,緊接著 5 次結構圖呼叫,而 `RateLimitBucketEnum.LLM` 是 **12 次/分鐘**。前兩張畫出來、其餘撞 429 後**無聲消失**——前端沒有任何訊息,使用者只看到「有些節有圖有些沒有」。

**修正**:逐張之間 `CARBON_DIAGRAM_THROTTLE_MS = 6000` 間隔,額度失敗後 `CARBON_DIAGRAM_QUOTA_RETRY_MS = 30000` 退避重試一次;三種失敗(無內容 / 護欄拒絕 / 呼叫失敗)各自記 log,不再靜默。

## 現象二:語意上無意義的時間軸

```
timeline
    2023年底 : 員工人數約為217人
    未標註時間 : 2023年底
```

兩個問題疊在一起:只有一個時間點(1.1 節被 gap-fill 改寫成公司簡介後已無沿革條目),而且模型把**時間標籤本身**當成了事件節點。

**修正**:`CARBON_TIMELINE_MIN_DATED_EVENTS = 3`,且**事件文字等於某個時間標籤者不計入**有效事件數;不足即顯示「素材不足」而非畫一張技術上合法、語意上荒謬的圖。

## 設計立場(值得記錄)

護欄擋不住語意荒謬——「員工人數 217 人」確實出現在原文,回溯檢查會通過。能擋的是**結構性的荒謬**:一個點不構成時間軸。這類規則要用結構條件表達,不要試圖讓 LLM 自我審查。

## 殘留

1.1 節之所以沒有沿革條目,根因是文字層降級(見 issue 01);那個修好之後 1.1 應該會有 23 個里程碑,時間軸就會正常出現。**這兩個 issue 的驗收要一起做。**
