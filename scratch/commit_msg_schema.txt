chore(schema): Finalize high-precision schema migration and ESG types

This commit implements Phase 6 of the enterprise audit roadmap by
hardening the database schema and ESG reporting types for Big 4
compliance standards:

1. Financial Precision Upgrade
   - Converted all `amount` fields across `Order`, `PaymentTransaction`,
     `Receipt`, and `VoucherLine` models from `Int` to `BigInt` to
     prevent potential overflow issues with large enterprise datasets.

2. ESG Metrics Strictness
   - Introduced the `MeasurementUnit` enum to enforce strictly typed
     units (e.g., KWH, LITER, TONNE) on the `EsgRecord` model, eliminating
     free-form string input errors.
   - Updated `src/interfaces/esg_report.ts` to allow `coefficient: number | null`
     to correctly represent and prevent "greenwashing" scenarios where missing
     carbon coefficients were incorrectly interpreted as 0 emissions.

3. Frontend & Reporting Adaptations
   - Updated the `esg_bom_table.tsx` component and `esg_report_generator.ts`
     to safely handle the new `null` coefficients and properly parse the
     high-precision `BigInt`/`Decimal` structures.
   - Updated tests (`balance_sheet_generator.test.ts`) to align with
     the new precision paradigms.
